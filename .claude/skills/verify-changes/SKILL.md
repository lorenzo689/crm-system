# Verify changes

## 1. What changed

`git status --short` and `git diff --stat` (plus untracked files). Note: `apps/web/AGENTS.md` is generated by `next dev` and never part of a change.

## 2. Choose checks (run every row whose paths changed)

| Changed paths | Run (from repo root unless noted) |
|---|---|
| any TS/TSX | `pnpm lint`, `pnpm typecheck` |
| `apps/web/**` | `cd apps/web && pnpm test`; `pnpm --filter my-app build` |
| `apps/api/src/**` | `cd apps/api && pnpm test`; `pnpm --filter api build` |
| API behaviour with HTTP/auth/roles/DB, `apps/api/test/**` | `cd apps/api && pnpm test:e2e` (full suite before a PR; single file while iterating: `pnpm test:e2e test/<file>.e2e-spec.ts`) |
| `apps/api/prisma/**` | apply to test DB: `DATABASE_URL=postgresql://bissinger:bissinger_dev@127.0.0.1:5432/bissinger_os_test pnpm exec prisma migrate deploy` then `… prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --exit-code` (in `apps/api`) |
| `package.json`, `pnpm-lock.yaml` | `pnpm install --frozen-lockfile`, `pnpm audit --prod` (assess by reachability) |
| `infrastructure/**/*.sh` | `bash -n <file>`; Docker tests (`infrastructure/tests/*.sh`) run in CI – say so if not run locally |
| always | `git diff --check` |

## 3. Run safely on this machine

- Foreground, one at a time, with a timeout. **Never two `test:e2e` runs at once** (same `_test` database → deadlocks, hook timeouts).
- Before `test:e2e`: no orphaned `jest` processes (PowerShell: `Get-CimInstance Win32_Process -Filter "Name='node.exe'" | ? CommandLine -match jest`).
- Use `127.0.0.1`, not `localhost`, for the test database (Docker Desktop stalls).
- If the full e2e suite exceeds the tool timeout, run it in the background with output to a file and wait for the result; do not start a second copy.
- Hook timeouts in suites unrelated to the change: check DB activity (`docker exec docker-postgres-1 psql -U bissinger -d bissinger_os_test -c "select pid,state,wait_event,left(query,60) from pg_stat_activity"`) and rerun once; report the flake, do not hide it.
- Do not restart Docker Desktop or other projects' containers without asking.

## 4. Report

A table with each check, the exact command, and the result (`passed N/N`, `green`, `failed: <first error>`, or `not run: <reason>`). Then: which CI jobs will cover what was not run locally, and remaining risks. A red check is reported as red, with its cause.

## Done when

- [ ] Every row matching the changed paths ran in this session, or is listed as "not run" with a reason
- [ ] Failures investigated to a cause (code or environment), never suppressed
- [ ] Results reported with commands and numbers
