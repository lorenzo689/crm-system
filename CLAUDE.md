# Bissinger OS – project rules for Claude Code

ERP/CRM for a lighting company. pnpm + Turborepo monorepo, German UI and docs.

## Map

- `apps/api` – NestJS 11, Prisma 7, PostgreSQL 17. Modules in `src/modules/<name>` (controller, service, repository, `dto/`). Schema and migrations in `prisma/`.
- `apps/web` – Next.js 16 (App Router, `app/(app)/…` = signed-in pages). Read the Next.js note above before writing web code.
- `packages/*` – shared configs; `api-client`, `api-contracts`, `ui` are currently not used by the apps.
- `docs/security/` (auth, sessions, CSRF, session context, job leases), `docs/deployment/` (staging, runbook, acceptance), `docs/decisions/`.

## Commands (from the repo root unless noted)

`pnpm lint` · `pnpm typecheck` · `pnpm test` (web tests + API unit) · `pnpm build` ·
`cd apps/api && pnpm test:e2e` (real PostgreSQL, database name must end in `_test`).
CI: `.github/workflows/ci.yml` runs all of these on every pull request, plus the Docker staging tests.

## Rules that always apply

- **Never weaken security.** Every controller uses `JwtAuthGuard`; roles via `RolesGuard` + `@Roles`; every query is scoped by the caller's `organizationId` (taken from the session on the server, never from the request); project-scoped writes use `ProjectWriteGuard`. Mutations rely on the session-bound CSRF token; no exemptions.
- **Browser requests only through `apps/web/lib/auth-api.ts` / `use-api.ts`** (session context, CSRF, cache isolation). No raw `fetch`, no direct document URLs.
- **Data:** synthetic test data only. No real company data, credentials, mail accounts or AI keys anywhere (code, tests, logs, commits).
- **Migrations:** additive by default, created with Prisma, checked with `prisma migrate diff`; never edit an applied migration.
- **Git:** no commit, push, PR, merge or deployment without the user's explicit approval. Never touch `main`. Never commit `apps/web/AGENTS.md` (generated by `next dev`) or `.env*`.
- **Evidence:** never claim a test, build or check passed unless it was run in this session; report failures with their output. Never skip tests or weaken assertions to get green.
- **Integration tests on this Windows machine:** run one `test:e2e` at a time (parallel runs on the same database deadlock); stop orphaned `jest` processes before starting another.
- **Reviews:** a review written by the agent that wrote the code is not independent; say so.
